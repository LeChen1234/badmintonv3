# 双来源羽毛球视频数据采集与标注协议

系统只假设两类可获得数据：网上公开的单机位比赛视频，以及自行使用手机拍摄的训练视频。两者通过统一的“击球事件”连接，但不强迫标注同等精度。

## 1. 为什么分成两条数据轨道

单张或远景比赛画面能支持的结论，与抵近、高清、连续训练视频不同。系统不再把所有视频按同一套精细程度处理。

### 比赛/动作时序轨

适合：

- 动作类别与动作阶段；
- 主动/受迫状态；
- 移动、站位、回合上下文和战术；
- 击球事件时间点。

不适合直接得出：

- 精细关节角和发力链结论；
- 拍面微小姿态、甜区位置等不可见细节；
- 单帧动作质量的精细分数。

每个比赛任务必须保存原视频链接或来源编号。来源不可追溯的数据不能作为正式发布数据。

### 抵近训练质量轨

适合：

- 完整动作序列；
- 动作质量与技术偏差；
- 清晰可见的身体、球拍和击球接触几何；
- 同一动作跨运动员、跨水平和跨视角比较。

必须记录目标动作、相对拍摄视角、机位高度、实际帧率和受试者编码。采集时应区分自然训练、指定标准动作和指定条件变化；不得把训练指令直接当成实际完成质量。

只有一部手机时，可以让同一运动员重复同一组动作：先拍后方广角，再拍侧方近景。两组视频填写相同桥接视角编号；相同条件的重复动作填写相同重复组编号。后方视角连接比赛域，侧方视角用于确认接触位置和动作机制。

## 2. 反光标记点图片如何使用

会议图片展示的是实际运动捕捉实验中的实体/反光标记点，包括身体、球拍和羽毛球布点。它们不是普通 RGB 比赛视频中应由模型“补出来”的真值。

系统中的“实体/反光标记点实验”只用于记录确实完成物理布点的受控采集。普通视频继续使用视频关键点方案；遮挡或模糊点必须标为不可见，不得把几何推测当作人工观测。

## 3. 多视角与跨视频身份

- 同一次动作采集的不同机位使用相同的“采集会话编号”。
- 每个视频分别记录正面、背面、左右侧、斜侧和机位高度。
- 同一受试者跨视频使用相同匿名受试者编码，不使用身份证号、手机号等直接身份信息。
- 当前系统不要求同一时刻同步多机位；先建立可追溯的会话和视角元数据，为后续多视角研究保留接口。

## 4. 数据有效性的最低条件

- 必须来自视频或有明确顺序的图像序列，不以孤立单帧替代动作过程。
- 原视频保留帧数、FPS、分辨率、时间戳和内容指纹。
- 模糊、遮挡、不可见字段保留空值，不作强行补全。
- 精细动作质量只在抵近训练质量轨启用。
- 导出数据包含采集场景、标注目标、视角、会话编号和目标动作，便于按数据用途分别训练和评估。
- 比赛来源字段与手机训练字段相互隔离，切换来源时不会把无关字段带入正式数据。
- 同一受试者、桥接视角、采集会话和重复动作组在研究划分中保持为连通组，不能跨训练集、验证集和测试集泄漏。

## 5. 双来源共同标注单元

正式样本单元不是孤立帧，而是一次完整击球事件：来球情境 → 动作执行 → 击球接触 → 击球后果。比赛视频优先填写情境和后果；手机训练优先填写执行和可见接触。所有结论同时记录可见性、证据来源与 1–5 级置信度。

JSON 2.2 导出会同时为逐帧记录和连续击球事件生成稳定研究划分；CSV 包含视频来源、手机采集设计、帧率、喂球、重复组和桥接视角字段。
