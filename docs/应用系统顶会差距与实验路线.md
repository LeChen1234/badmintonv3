# 应用系统顶会差距与实验路线

## 核心判断

当前系统已经不是普通 CRUD 标注工具，但还不能仅凭“功能完整”投稿。论文贡献应收敛为：**面向高速、稀疏接触事件的可解释信息泛函采样与人机协同数据闭环**。系统是验证该方法的载体，数据效用、人工成本和跨域稳健性才是主结果。

## 已经补齐的可审查证据

- 每次研究导出生成内容 SHA-256、稳定 dataset ID、协议版本与确定性分组切分。
- 以匿名运动员和比赛构成的连通分量分组；共享运动员或比赛的数据均不跨 train/validation/test。切分种子和比例来自 `config/research_protocol.json`。
- 论文发布门禁检查锁定状态、场次数、类别数、姿态覆盖率、稳定身份和空切分。
- 已锁定任务禁止修改标注和比赛/运动员元数据，保证数据版本语义不可变。
- 保存辅助算法版本、置信度、采纳状态、标注耗时，以及每次人工修订的前后快照。
- 提供等类别预算、固定专家测试集、分组泄漏检测的微型训练 A/B。

## 当前仍不足的部分

### P0：没有这些，主实验不成立

1. **专家裁决的自动融合仍需研究。** 系统已支持主标注员与独立复标员、答案隔离、Kappa/PCK、一屏关键点叠加和唯一 gold 选择；下一步可研究基于关节置信度的候选融合，并与专家选择做消融。
2. **匿名身份需要运营约束。** 已引入跨比赛 `subject_code` 和运动员—比赛连通分量切分，但仍需建立编码签发、重复检测和隐私映射保管制度。
3. **在线闭环仍需真实轮次验证。** 系统已经把微训练 Macro-F1、方差、人时和组件消融增益反馈为下一轮泛函权重，并用边际收益 95% 上界执行预注册停止；目前仍缺真实多轮实验来验证权重更新优于固定权重。
4. **缺少真实对照实验数据。** 需要相同视频池、相同人时预算下比较 Random、Uniform Temporal、Entropy、Core-set/Clustering、现有信息泛函和完整系统。

### P1：决定论文强度

1. 建立跨场馆、机位、光照、运动员水平的数据切片，报告 worst-group 与跨域性能，而不只报告平均值。
2. 把动作识别、关键点估计和接触事件定位分成三个任务，分别报告 Macro-F1、PCK/OKS、temporal mAP/接触帧误差。
3. 增加主动学习曲线：指标相对累计人时、累计标注帧数和累计专家修订数，而不只比较最终点。
4. 对运动、熵、DCT、速度/加速度/jerk、时间去冗余和复核优先级逐项消融。
5. 报告系统工程指标：并发标注延迟、推理吞吐、任务失败恢复、导出可复现性和数据删除审计。

## 最小可投稿实验流程

1. 冻结 taxonomy、研究协议、测试比赛和评价代码。
2. 从同一未标注池构造五种等人时采样策略，每种至少三个随机种子。
3. 对 10% 盲法重复标注并专家裁决，报告一致性与争议类型。
4. 每一轮微训练后记录验证收益，直到单位标注成本收益低于预注册阈值。
5. 最终仅在冻结测试集评测一次，并报告 bootstrap 95% CI 和配对检验。
6. 发布 dataset ID、SHA-256、切分 manifest、配置、模型权重、环境和失败案例。

## 推荐贡献表述

不要把信息论、泛函、DCT 和微积分分别包装成多个创新点。更可信的表述是：系统把多源时序变化映射为一个可解释、可消融的信息效用泛函，并通过时间去冗余、人工不确定性复核和下游微训练反馈，优化单位专家人时产生的数据效用。
