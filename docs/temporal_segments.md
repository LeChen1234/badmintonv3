# 连续动作片段标注

## 目的

逐帧抽样适合人体姿态和击球接触关键帧，但不能稳定表达完整动作的开始、发展与结束。连续动作片段以原视频时间轴为依据，把动作类型和阶段绑定到一个起止区间。

## 数据结构

- `task_batch_id`：所属视频任务。
- `selected_player_id`：执行动作的人物。
- `start_frame`、`end_frame`：抽取帧序列中的闭区间。
- `start_timestamp_ms`、`end_timestamp_ms`：服务器从原视频帧记录读取，客户端不能自行填写。
- `action_type`：动作类型，使用当前标注分类规范。
- `action_phase`：可选阶段；学生不能填写，交由专家判定。
- `context`：来球高度、深度、主动/均势/被迫状态等情境。
- `execution`：到位、接触相对身体位置、回位和可观察错误机制。
- `outcome`：落点深度、对手响应和回合效果。
- `evidence`：情境/接触/后果可见性、证据依据和置信度。
- `status`：`draft`、`submitted`、`confirmed`。

## 约束

1. 起止帧必须真实存在，且结束帧不早于开始帧。
2. 同一标注员、同一人物的动作片段不能重叠，避免相互矛盾。
3. 学生只能查看和修改自己的片段；专家、组长和管理员可查看全部片段。
4. 已确认片段不能修改或删除。
5. JSON 数据集导出只包含已确认片段。
6. 不可见内容填写 `unknown` 或 `not_visible`，不得以动作常识补齐画面中不存在的证据。

## 与单帧标注的关系

连续片段回答“哪段时间发生了什么动作”；单帧记录回答“某个关键时刻人物姿态和接触几何是什么”。两者互补，不应把片段标签机械复制为大量相同单帧记录。
